# Jelluvi spatial concepts

These directions are local design studies, not approved production screens. None is wired into the
public site or the Cloudflare build. All three reuse the corrected, non-generative mascot model.

## Shared conceptual rules

1. The mascot must perform the product action, not decorate a block beside it.
2. Motion must explain input, local transformation, format choice, or user-owned output.
3. Every visible object must map to a true product concept; generic decorative geometry is excluded.
4. The experience must avoid a catalogue of equally weighted cards. Hierarchy comes from depth,
   movement, scale, and a single active story.
5. The final interaction must point to an owned local file, because ownership is the product payoff.

## 01 · The Living Keeper

**Product framing:** Jelluvi is the transformation itself.

| Element | Visible role | Conceptual and semantic reason |
| --- | --- | --- |
| Oversized mascot portal | Receives the incoming chat fragments | Makes the brand inseparable from the primary action: turning a conversation into a file |
| Conversation rows | Move from the source side toward the mascot | Represents real input instead of decorative particles |
| Double privacy ring | Defines a contained processing zone | Makes the local-only boundary visible without technical diagrams |
| Volumetric Markdown file | Appears after the mascot processes the stream | Ends on the owned artifact rather than a marketing promise |
| Absorb → squash → release motion | Connects the three visible states | Gives motion a causal product meaning rather than ambient spectacle |

## 02 · Format Cosmos

**Product framing:** one prepared conversation powers a system of portable outcomes.

| Element | Visible role | Conceptual and semantic reason |
| --- | --- | --- |
| Calm mascot nucleus | Anchors the centre | Signals one consistent local engine behind every output |
| Nine named format nodes | Occupy different points in depth | Shows true export breadth without returning to a flat grid of cards |
| Shared orbit | Connects every node | Explains that all outputs come from the same source conversation |
| Selected-format beam | Links the nucleus to one highlighted node | Establishes a legible future selection interaction and current focus |
| Slow orbital motion | Lets depth and hierarchy reveal themselves | Makes exploration feel deliberate rather than like a busy feature carousel |

## 03 · Memory Current

**Product framing:** preserve the continuity of the conversation beyond the platform.

| Element | Visible role | Conceptual and semantic reason |
| --- | --- | --- |
| Continuous luminous thread | Crosses the full spatial stage | Represents sequence, context, and continuity — the main value of a conversation |
| Ordered message fragments | Travel along the same curve | Shows that export preserves order rather than producing disconnected snippets |
| Local gateway ring | Marks one bounded transition point | Explains the technical boundary through a spatial event, not jargon |
| Mascot guide | Accompanies the thread instead of swallowing it | Frames Jelluvi as a trusted guide when continuity is the emotional emphasis |
| ZIP archive endpoint | Fixes the end of the current | Returns final ownership to the user and closes the narrative loop |

## Decision lens

- Choose **The Living Keeper** for the strongest mascot memory and clearest single conversion story.
- Choose **Format Cosmos** when export breadth is the main competitive differentiator.
- Choose **Memory Current** when emotional continuity and local privacy should lead the brand.
